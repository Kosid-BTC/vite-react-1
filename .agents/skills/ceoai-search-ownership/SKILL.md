# CEO AI Thailand — Search Ownership Improvement Loop

## Purpose

Build Search & Entity Intelligence as a sensor and continuous-improvement loop inside CEO AI Thailand Growth OS.

Do not implement this as a standalone SEO tool. Reuse the existing Marketing Measurement, Evidence, Diagnosis, Next Best Action, Experiment, Outcome, and Learning contracts wherever they exist.

## Strategic origin

Preserve this decision chain as the rationale for the system:

`Google Brand Confusion -> Crisis-to-Opportunity -> clarify CEO + AI + Thailand semantic space -> Risk/Opportunity assessment -> PROCEED_WITH_CONTROLS -> Canonical Entity -> Search Ownership -> Category Ownership -> ECI -> Growth Core -> Action -> Measurement -> Learning -> next cycle`

The problem is not simply poor keyword ranking. Search systems may interpret `ceoaithailand` broadly across CEO, AI, Thailand, executive programs, awards, and adjacent entities. The opportunity is to establish a clear canonical entity and progressively own qualified semantic territory.

Never solve ambiguity with keyword stuffing or mass AI content.

`ceoaithailand -> CEO AI Thailand -> AI Business Operating System -> people starting businesses + Thai SMEs`

## The Continuous Improvement Cycle

Implement the domain as a repeatable state loop.

### C0 — Observe Brand Confusion

Collect trusted evidence from Search Console, SERP observations, owned-site audits, verified social properties, and other approved search evidence.

Output:

- observations
- provenance
- reliability
- observation window

Do not infer search-engine facts from unsupported analytics data.

### C1 — Convert Crisis to Opportunity

Classify the observation as one or more opportunity types:

- `BRAND_RESOLUTION`
- `CATEGORY_ASSOCIATION`
- `PROBLEM_DEMAND`
- `ADJACENT_SEMANTIC_SPACE`

The system must distinguish an opportunity from a proven outcome.

### C2 — Semantic Decomposition

Map demand into the four Search Ownership rings.

`BRAND`
- CEO AI Thailand
- ceoaithailand
- CEOAIThailand
- CEO AI ไทย

`CATEGORY`
- AI สำหรับ SME ไทย
- AI Business Operating System
- AI Marketing สำหรับ SME
- AI ช่วยเริ่มธุรกิจ

`PROBLEM`
- เริ่มธุรกิจยังไง
- หาลูกค้ารายแรก
- ทดสอบไอเดียธุรกิจ
- ทำการตลาดด้วย AI
- วัดผลการตลาดยังไง

`ADJACENT`
- CEO Thailand
- Digital CEO
- AI CEO
- CEO ยุค AI
- หลักสูตร CEO

Use deterministic/rule-based classification first. AI may propose reclassification but must not silently rewrite historical classifications.

### C3 — Risk / Opportunity Assessment

Create an evidence-linked assessment before recommending action.

At minimum evaluate:

- strategic fit
- qualified acquisition potential
- brand/entity confusion risk
- execution cost/risk
- legal/reputation risk
- platform dependency
- evidence quality

Result must be one of:

- `PROCEED`
- `PROCEED_WITH_CONTROLS`
- `HOLD_FOR_EVIDENCE`
- `DO_NOT_PROCEED`

Store rationale and evidence references. AI may propose; human authority remains final for material strategic decisions.

### C4 — Canonical Entity Control

Audit and normalize, with human-safe controls:

- canonical brand name
- Entity Hub
- title/H1/meta description
- Organization schema
- WebSite schema
- stable `@id`
- verified `sameAs`
- logo/name metadata
- internal linking
- official profile naming recommendations

Prefer one canonical Entity Hub such as `/about`, unless the repository already has a stronger single canonical route.

Do not create duplicate canonical entity pages or conflicting Organization nodes.

### C5 — Search Ownership

Measure whether verified owned properties increasingly occupy branded search space.

Key measures:

- Brand Search Ownership
- Owned SERP Coverage
- Branded Search Impressions
- Branded CTR
- Average Position
- Entity Recognition

Treat `Owned SERP Coverage > 70%` as a target hypothesis, not current truth.

### C6 — Category Ownership

Measure whether CEO AI Thailand begins appearing for qualified category demand such as AI for Thai SMEs and AI Business Operating System.

Do not equate one ranking or one AI citation with category ownership.

Prefer improving an existing relevant page before creating a new overlapping page.

### C7 — Entity Confusion Index

ECI is an internal CEO AI Thailand metric. It is NOT a Google metric.

Lower is better.

Version: `eci.v1`

`EntityStrength = 0.30*B + 0.25*S + 0.20*O + 0.15*Q + 0.10*A`

Where:

- `B` = Brand Consistency
- `S` = Structured Entity Consistency
- `O` = Owned SERP Coverage
- `Q` = Branded Query Dominance
- `A` = Association Accuracy

`ECI = 100 - EntityStrength`

Classification:

- 0–20: `CLEAR`
- 21–40: `LOW_CONFUSION`
- 41–60: `CAUTION`
- 61–100: `HIGH_CONFUSION`

If required inputs are missing, return `INSUFFICIENT_DATA` and list missing signals. Never invent components merely to show a score.

Keep directionality explicit:

- Entity Health: higher is better
- ECI: lower is better

### C8 — Growth Core Diagnosis

Transform trusted Search/Entity observations into existing Growth Core evidence.

Required flow:

`Observation -> Evidence -> Diagnosis -> NBA Proposal`

Do not create a second recommendation engine if Growth Core already provides these concepts.

Search evidence must not directly mutate Business Genome or approved strategy.

### C9 — Next Best Action

Start deterministic before autonomous AI.

Examples:

- High ECI + weak entity consistency -> propose Entity Hub / structured-entity normalization.
- Branded impressions rising + weak branded CTR -> propose a controlled title/meta test.
- Category impressions present + weak relevant page -> improve existing page before creating another.
- Low Owned SERP Coverage -> inspect entity consistency, official-profile consistency, internal links, and Entity Hub before recommending content volume.

Every NBA must include:

- evidence
- diagnosis
- proposed action
- expected learning
- primary KPI
- guardrails
- review window
- approval state

AI proposes. Human decides where approval is required.

### C10 — Controlled Action

Actions may include:

- entity metadata/schema improvements
- internal linking
- Entity Hub improvement
- useful content improvement/creation
- title/meta experiment
- content derivative generation
- official-profile recommendation

Do not auto-publish risky comparison content. Do not auto-change external profiles without explicit authorization and the appropriate connected tool.

### C11 — Content / Creative Automation

Use Search Evidence as an input to the existing content system:

`Audience x Pain x Search Intent x Evidence x Content Pillar x Funnel Stage`

Required content workflow:

`Evidence -> Search Intent -> Existing Content Gap -> Unique Insight -> Useful Content -> Human Review -> Publish -> Measure`

Never default to:

`Keyword -> generate many articles -> auto-publish`

One evidence-backed content concept may produce coordinated derivatives:

`Article -> Short Post -> Carousel -> Text-to-Image -> Text-to-Video -> Image-to-Video -> YouTube/Social`

Preserve lineage from source evidence to content item, creative version, distribution, and outcome.

### C12 — Measure Outcome

Measure business and search outcomes, not rankings alone.

Preferred funnel:

`Search Visibility -> Qualified Visit -> Intent Event -> Activation -> Lead -> Customer`

Reuse the existing Marketing Measurement event taxonomy where available, including stronger intent events such as `calculator_complete`, `assessment_complete`, `signup_complete`, and `trial_started` when implemented.

### C13 — Learn

Create a learning record that answers:

- What changed?
- What evidence supports it?
- Did the hypothesis pass, fail, or remain inconclusive?
- What should remain stable?
- What should be tested next?
- What is the evidence reliability?

Learning may update future recommendations. It must not rewrite historical evidence.

### C14 — Start Next Cycle

Feed validated learning back into the next observation cycle.

`Learn -> Observe -> Reassess -> Next Best Action`

The loop never assumes permanent ownership. Search and platform conditions can change.

## Cycle State Contract

Prefer explicit states such as:

- `OBSERVED`
- `OPPORTUNITY_CLASSIFIED`
- `RISK_ASSESSED`
- `ENTITY_CONTROLLED`
- `OWNERSHIP_MEASURED`
- `ECI_EVALUATED`
- `DIAGNOSED`
- `NBA_PROPOSED`
- `APPROVED`
- `ACTIONED`
- `MEASURED`
- `LEARNED`
- `CLOSED`

Store timestamps and actor/source for state transitions. Avoid hidden state changes.

## Evidence Reliability

Every metric or diagnosis must expose one of:

- `RELIABLE`
- `CAUTION`
- `INSUFFICIENT_DATA`
- `UNAVAILABLE`

Trusted provider metrics such as GSC/SERP observations must use a server/provider ingestion boundary. Ordinary browser clients must not fabricate trusted provider metrics.

## Search Health UX — Law of UX

Do not make the default view a dense SEO dashboard.

Default hierarchy:

1. Entity Recognition
2. Search Ownership
3. Qualified Demand
4. Main Problem
5. Why It Matters
6. Next Best Action
7. One primary CTA

Keep advanced metrics behind progressive disclosure.

Never show fabricated scores to make the dashboard appear complete.

## Comparison / Adjacent Content Safety

Use only verified public information for third-party comparisons.

Prefer neutral dimensions:

- objective
- target audience
- service/product type
- format
- use case
- business stage

Avoid superiority claims, disparagement, implied affiliation, unsupported feature comparisons, or negative speculation.

Require human review before publishing comparison content.

## Claim Safety

Audit SEO-visible claims and classify them as:

- `VERIFIED`
- `NEEDS_EVIDENCE`
- `REMOVE_OR_REWRITE`

Flag unsupported customer counts, rankings, `best`/`#1`, guaranteed outcomes, unverifiable testimonials, ratings, awards, and affiliations.

Never replace one unsupported claim with another.

## Platform Dependency Control

Search is acquisition, not the customer relationship.

Prefer:

`Search/Social/Video -> Website -> Useful Tool/Assessment -> Account/First-party identity -> Activation -> Ongoing relationship`

The system should optimize for qualified first-party relationships, not dependence on one ranking algorithm.

## Implementation Order

When this skill is invoked for implementation, proceed in this order unless repository evidence requires a safer dependency order:

1. Inspect current repository architecture and existing SEO/Growth Core/Measurement implementation.
2. Create or consolidate the Entity Registry / canonical brand source of truth.
3. Implement deterministic query classification and entity consistency audit.
4. Implement ECI domain logic with `INSUFFICIENT_DATA` behavior.
5. Add trusted Search Evidence contracts/ingestion boundaries.
6. Map Search Evidence into existing Growth Core Evidence/Diagnosis/NBA.
7. Implement deterministic NBA rules and approval boundaries.
8. Build Search Health UX using Law of UX.
9. Connect evidence-backed content/creative actions without auto-publishing.
10. Add cycle outcome/learning records and feed validated learning into the next cycle.
11. Add focused tests.
12. Run repository lint, tests, and build.

Do not mutate production or deploy automatically unless explicitly requested and authorized.

## Database / Domain Rules

Inspect existing tables before adding schema. Reuse existing Evidence, Diagnosis, NBA, Experiment, Outcome, and Learning entities.

Add only minimum forward-compatible Search/Entity structures, potentially including:

- search query definitions/classifications
- search observations
- SERP observations
- entity health snapshots
- entity metric components
- search-content mappings
- improvement-cycle runs/state transitions

Every tenant-owned record must contain `workspace_id` and follow existing RLS/multi-tenant conventions.

Do not weaken frozen security architecture. Do not edit frozen migrations; use forward-only migrations.

## Measurement Cadence

Use signal-appropriate windows:

- Daily: ingestion/tracking health
- Weekly: execution, indexation, entity consistency
- 28 days: Search Ownership, category movement, ECI, NBA review
- 56–84 days: branded-search trend, brand memory, Owned SERP, category association

Do not reverse strategy from a short noisy window without sufficient evidence.

## Required Tests

Cover relevant changes:

- canonical brand remains `CEO AI Thailand`
- aliases never replace canonical Organization name
- only one canonical Organization entity exists
- `sameAs` contains only verified configured URLs
- ECI formula and direction are correct
- missing ECI evidence returns `INSUFFICIENT_DATA`
- branded aliases classify as `BRAND`
- unrelated CEO queries do not classify as `BRAND`
- trusted provider evidence cannot be fabricated by ordinary clients
- search evidence cannot directly mutate approved strategy
- NBA requires the correct approval state
- mass-content publication is not a default action
- cycle transitions are auditable
- existing SEO routes/structured data remain valid
- tenant isolation/RLS remains intact

## Definition of Done

A Search Ownership improvement cycle is complete only when:

- canonical identity is preserved
- evidence provenance is explicit
- risk/opportunity assessment is recorded
- ECI does not fabricate confidence
- Search Evidence integrates with Growth Core
- NBA remains proposal-first with human authority where required
- controlled action is linked to its hypothesis
- outcome is measured
- learning is recorded
- learning feeds the next cycle without rewriting history
- relevant tests, lint, and build pass
- production mutations are explicitly reported
